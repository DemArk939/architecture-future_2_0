## Целевой технологический стек (Technical Radar)

Радар разделён на четыре квадранта: Техники и паттерны, Инструменты и платформы, Хранилища и форматы данных,
Процессы и роли. Статусы соответствуют методологии Thoughtworks:

- Adopt — технологии, готовые к промышленному использованию
- Trial — технологии, которые стоит пробовать на пилотных проектах
- Assess — технологии для изучения и оценки
- Hold — технологии, от которых стоит воздержаться

### Quadrant 1: Архитектурные паттерны и техники

| Технология/Паттерн              | Статус | Обоснование                                                                                              |
|:--------------------------------|:------:|:---------------------------------------------------------------------------------------------------------|
| Data Mesh                       | Trial  | Децентрализованный подход, требующий культурных изменений. Пилот в 1-2 доменах подтвердит эффективность. |
| Event-Driven Architecture (EDA) | Adopt  | Основа целевой архитектуры. Событийная шина (Kafka) уже доказала эффективность в пилотах.                |
| Data as a Product               | Trial  | Концепция владения данными внутри доменов. Требует внедрения культуры Product Owner'ов данных.           |
| Self-service BI                 | Adopt  | Портал самообслуживания (Superset + Trino) полностью реализован и используется бизнесом.                 |
| CQRS                            | Assess | Может потребоваться для сложных доменов (например, Billing), но не является обязательным на старте.      |
| Saga Pattern                    | Assess | Для распределённых транзакций (например, оплата + резерв товара). Будем оценивать в потоковых сценариях. |

### Quadrant 2: Инструменты и платформы

| Технология/Паттерн             | Статус | Обоснование                                                                                                    |
|:-------------------------------|:------:|:---------------------------------------------------------------------------------------------------------------|
| Apache Kafka (MSK / Confluent) | Adopt  | Центральная шина событий, проверена в пилоте.                                                                  |
| Trino                          | Adopt  | SQL-движок для федеративных запросов, обеспечивает единый доступ к данным.                                     |
| Apache Flink                   | Trial  | Потоковая обработка в реальном времени. Используется для Silver/Gold-слоёв, но требует наращивания экспертизы. |
| Kafka Connect                  | Adopt  | Надёжный инструмент для интеграции источников и стоков (S3, БД).                                               |
| Debezium (CDC)                 | Adopt  | Захват изменений из БД доменов — ключевой механизм публикации событий.                                         |
| Superset                       | Adopt  | Визуализация и дашборды для портала самообслуживания.                                                          |
| JupyterHub                     | Adopt  | Среда для исследовательского анализа (data science).                                                           |
| Airflow                        | Adopt  | Оркестрация пакетных задач (там, где потоковая обработка нецелесообразна).                                     |
| Amundsen                       | Trial  | Каталог данных, пилот в одном домене для оценки удобства.                                                      |
| Apache Ranger                  | Assess | Централизованное управление доступом. Будем пилотировать после масштабирования доменов.                        |
| Great Expectations             | Trial  | Фреймворк качества данных, внедрён в потоковые пайплайны.                                                      |
| OpenLineage + Marquez          | Assess | Сбор lineage данных — для соответствия регуляторным требованиям.                                               |
| Power BI                       |  Hold  | Сохраняется для совместимости, но новые отчёты разрабатываются в Superset.                                     |
| Apache Camel                   |  Hold  | Только как антикоррупционный слой для legacy-интеграций, выводится.                                            |

### Quadrant 3: Хранилища и форматы данных

| Технология/Паттерн             | Статус | Обоснование                                                                         |
|:-------------------------------|:------:|:------------------------------------------------------------------------------------|
| Data Lake (S3 / Cloud Storage) | Adopt  | Центральное хранилище для всех данных (Bronze/Silver/Gold).                         |
| PostgreSQL                     | Adopt  | Основная БД для микросервисов доменов (Patient, Appointment, и др.).                |
| Parquet + ORC                  | Adopt  | Оптимальные форматы для аналитических запросов в Data Lake.                         |
| Apache Iceberg / Delta Lake    | Assess | Для обеспечения ACID-транзакций в Data Lake. Оценка после стабилизации архитектуры. |
| Avro (Schema Registry)         | Adopt  | Формат событий в Kafka с управлением схемами.                                       |
| SQL Server 2008                |  Hold  | Легаси-система, только read-only доступ до завершения миграции.                     |

### Quadrant 4: Процессы и роли

| Технология/Паттерн              | Статус | Обоснование                                                                   |
|:--------------------------------|:------:|:------------------------------------------------------------------------------|
| Data Product Owner              | Trial  | Новая роль, отвечающая за данные как продукт в рамках домена.                 |
| Domain Data Steward             | Trial  | Обеспечение качества и governance внутри домена.                              |
| Platform Engineer               | Adopt  | Команда, развивающая self-service платформу данных (Kafka, Trino, Data Lake). |
| Federated Governance            | Trial  | Глобальные стандарты + локальная автономия доменов.                           |
| CI/CD для данных (DataOps)      | Adopt  | Автоматизация развёртывания пайплайнов и проверок качества.                   |
| Contract Testing (схем событий) | Adopt  | Обязательная валидация совместимости схем через Schema Registry.              |
